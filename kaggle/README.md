# Running SensorFM on Kaggle (free tier)

Kaggle Notebooks give free CPU sessions and a weekly GPU quota (T4 ×2 or P100). Check the current
quota in your Kaggle settings; it changes. Nothing here costs money.

## Driven from the Mac (preferred, no clicking)

`scripts/kaggle_ctl.py` uses the `kaggle` CLI (already logged in): `push-code` uploads `git
archive HEAD` as the private dataset `sensorfm-code` (no GitHub token needed), `push JOB` starts a
private script kernel (`build-data` on CPU; `ladder-scaling`, `pretrain`, `downstream` on GPU T4
x2), later jobs mount earlier outputs with `--after`, and `pull NAME --import-results` brings
`results/` back. See the module docstring for the full sequence. The notebooks below are the
manual alternative.

## One-time setup (manual notebooks only)

1. Push this repo to GitHub (private is fine). If private, create a fine-grained read-only token
   and add it as a Kaggle **Secret** named `GH_TOKEN` (Add-ons → Secrets).
2. Optional: add `HF_TOKEN` (read-only Hugging Face token) as a Secret. It raises Hub rate limits
   for the LOTSA download.

## Step 1 — build data (CPU session, Internet ON) — notebook provided

1. Kaggle → **Create → New Notebook → File → Import Notebook** → upload
   `kaggle/notebooks/01_build_data.ipynb` from this repo.
2. Right panel: **Accelerator: None**, **Internet: On**; **Add-ons → Secrets**: `GH_TOKEN`
   (and optionally `HF_TOKEN`), each toggled on for this notebook.
3. **Run All**. Expect ~1–2 h (downloads ~5 GB of LOTSA arrow files to `/tmp`, writes ~0.5–1 GB
   of shards). The last cell prints the corpus summary and manifest hash.
4. **Save Version → Save & Run All (Commit)**. When it finishes: notebook **Output** tab →
   **New Dataset** → name `sensorfm-data`, **Private**.

Validated beforehand on 5 real subsets locally (multivariate + covariate formats, decontamination
against the full downstream reference, training on the resulting shards).

## Step 2 — GPU phase (after Checkpoint 2 approval) — notebooks provided

Import each notebook the same way as step 1; attach the `sensorfm-data` dataset as input.

| Notebook | Accelerator | ≈ session-hours | What it does |
|---|---|---|---|
| `02_ladder_scaling.ipynb` | GPU T4 x2 | 1.1 | throughput ladder + profiler traces (1 GPU), DDP/FSDP2 scaling (1 vs 2 GPUs) |
| `03_pretrain.ipynb` | GPU T4 x2 | ≤ 11.5 per session | DDP pretraining; stops with a checkpoint before the 12 h limit; to continue, attach the previous version as input and set `RESUME = True` |
| `04_downstream.ipynb` | GPU T4 x1 | ~4.5 | RUL / bearing / forecasting / UCR for the checkpoint and its from-scratch twin, Chronos zero-shot, paired comparisons; then deployment: ONNX + INT8 variants and TensorRT FP16/INT8 engines with metric deltas and latency |

Download each run's `results/` (Output tab) back into the repo's `results/`, then `make report`.
Kaggle charges quota per **session**-hour, so T4 x2 DDP gets ~2× the training per hour of quota.
Notebooks are generated by `kaggle/make_notebooks.py`.
